# 11. 디자인/UX 가이드라인

> [메인 README](../../README.md) · 이전: [10. 외부 서버에 배포하기](10_deploy_readme.md)

새 화면을 만들거나 기존 화면을 고칠 때 지키는 UI/UX 규칙 모음입니다. CSS 톤(색상/여백/버튼 등)은
`com.css` 의 "2026 UI 현대화 오버레이"가 전역으로 처리하므로 여기서는 다루지 않고, **레이아웃/상호작용
패턴** 위주로 적습니다.

## 등록/수정/상세 화면은 모달(팝업)로

- 사용자 피드백(2026-11-06): "수정창이나 등록창이나 조회창들은 팝업? 모달창으로 보는게 좋을것 같다."
- **현재 상태**: 상속받은 공통컴포넌트 화면 대부분과 이번에 새로 만든 전자결재(`apv`) 모듈은
  등록/수정/상세를 **별도 페이지 이동**(iframe 내 `go()` 네비게이션, 또는 `window.open` 새 창) 방식으로
  구현되어 있습니다. 아직 모달 방식으로 전환하지 않았습니다.
- **앞으로 새로 만드는 등록/수정/상세 화면은 모달(인페이지 오버레이)을 우선 검토**합니다. 특히:
  - 목록 화면에서 한두 개 필드만 빠르게 보거나 고치는 경우(예: 결재 상세+승인/반려, 템플릿 간단 수정)
  - 이미 `js/egovframework/com/cmm/modal.js`(`$(trigger).egovModal('modalId')`)가 벤더링되어 있어
    새 라이브러리 없이 바로 쓸 수 있음 — 마크업 예시는 `WEB-INF/jsp/egovframework/com/cmm/EgovModal.jsp` 참고
  - iframe(`contentFrame`) 안에서 그대로 열리므로 셸(사이드바/헤더)을 벗어나지 않는 장점이 있음
- **예외**: 상속받은 ~150개 공통컴포넌트 JSP(게시판, 쪽지, 일정 등)는 전면 재작업 대상이 아니므로
  유지보수 중 자연스럽게 손대는 경우가 아니면 급하게 모달로 바꾸지 않습니다. 새로 만드는 모듈부터 적용합니다.
- **적용 후보(우선순위)**: 전자결재 결재함의 "상세보기+승인/반려" 팝업(PR4에서 바로 모달로 구현 예정),
  전자결재 양식 템플릿의 간단 수정.

## 결정 전 참고

- 전체 페이지 전환이 더 적합한 경우(내용이 길어 모달 안에 다 넣기 어려운 등록 폼, 별도 URL로 공유/북마크가
  필요한 화면)는 기존 방식을 유지해도 됩니다. 모든 화면을 기계적으로 모달화하지는 않습니다.
